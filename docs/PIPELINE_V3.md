# Архитектура v3: субтитры — единственный источник данных

## Автоматический конвейер по исходной записи (обновление 6 октября 2026)

Используется **загруженная запись экрана**. Приложение не создаёт новую запись
и не воспроизводит действия в 1С или другой программе. `raw_video.mp4` сохраняется
без изменений. Видеоряд и его временная шкала сохраняются; исходная аудиодорожка
заменяется синтезированной речью. Заставки добавляются вокруг готового видео.

Новый маршрут: загрузка → распознавание речи автора → осторожная очистка сценария
→ субтитры → выбранный голос → анализ кадров и курсора → аннотации → готовый MP4.
Сведения ниже об обязательном ручном вводе текста относятся к предыдущему режиму.

- В форме загрузки доступны выбор Yandex/OpenAI, голос, образец звучания, темп,
  название, начальная и финальная заставки. Настройки хранятся в `lesson_options.json`
  отдельно для каждого урока. Ключи остаются на сервере. Изменение голоса сбрасывает
  устаревшие озвучку, аннотации и финальную сборку.
- `automatic_script_service.py` использует существующий STT. Для точной привязки
  предпочитаются faster-whisper или OpenAI; Yandex v1 в текущем адаптере возвращает
  только время большого фрагмента и требует проверки. Включены word timestamps
  для faster-whisper. ИИ-редактор обрабатывает ограниченные партии сегментов.
  Проверки чисел, отрицаний, названий, состава действий и степени изменения текста
  не дают незаметно принять опасную правку. Исходная фраза сохраняется в отчёте.
- Уверенный сценарий сохраняется автоматически. При низкой уверенности, неверном
  ответе редактора или отсутствии звука процесс останавливается на экране проверки.
  Пользователь видит исходную фразу, сценарий и кадр. Сохранённый ручной текст
  не перезаписывается при повторном входе или запуске конвейера.
- Текст для произношения и субтитры происходят из одного сценария. Каждый TTS-блок
  приводится к PCM 48 kHz mono. Выбранный сервис не заменяется другим незаметно.
  Невмещающаяся озвучка останавливает обработку с указанием блока: предложения
  не обрезаются, последующая речь не сдвигается относительно действий на экране.
- `screen_annotation_service.py` отправляет три кадра исходного видео рядом с
  действием в vision-модель (`SCREEN_ANALYSIS_MODEL`, по умолчанию `gpt-4o`).
  Надписи, объект и видимый курсор используются вместе. Курсор может быть не виден;
  события кликов из MP4 не извлекаются как точные системные события.
  Координаты принимаются автоматически только при уверенном результате на всех
  трёх кадрах и согласованных границах объекта. Большие перемещения и исчезновение
  объекта отправляются на проверку. Выделение ограничивается проверенным интервалом
  и ближайшей обнаруженной сменой кадра, небольшое движение учитывается по треку.
- Для vision нужен существующий `OPENAI_API_KEY`. При его отсутствии или ошибке
  доступны OCR-подсказки и ручная проверка. OCR-совпадение само по себе не утверждает
  аннотацию. Уверенность vision — оценка модели, а не гарантия точности.
- Спорные аннотации представлены списком: «Указать объект на кадре» или «Пропустить».
  Нерешённые предложения сохраняются при сохранении остальных выделений.
  Ручная правка координат сбрасывает автоматический трек для данного объекта.
- Если все аннотации уверенные, конвейер сам утверждает их и собирает файл.
  Иначе сборка идёт после проверки. Рамки и стрелки плавно появляются и исчезают.
  Заставки длятся по две секунды; они не меняют внутренние таймкоды урока.
- При ошибке прожига субтитров или наложения аннотаций сборка прекращается:
  неполный результат не выдаётся за успешно собранную инструкцию.

Отчёты: `script_review_report.json`, `voiceover_timing_report.json`,
`screen_analysis_report.json`, `assembly_report.json`.

API: `GET /voices`, `POST /voices/preview`, `GET/PUT /jobs/{id}/options`,
`POST /jobs/{id}/automatic`. В существующем уроке используйте блок «Голос и оформление
текущего урока» → «Обработать исходную запись автоматически».

Проверки: unit-тесты защиты сценария, координат и настроек; интеграционный тест
реальной сборки через FFmpeg проверяет замену звука, сохранение исходного файла,
субтитры, стрелку и длительность заставок. Качество распознавания и координат на
произвольных пользовательских записях требует отдельной проверки на реальных уроках.

---

Пользователь видит **четыре** этапа. Всё остальное работает внутри и на экране не показывается.

| № | Этап (UI id) | Что делает пользователь | Что делает программа |
|---|---|---|---|
| 1 | Загрузка видео (`upload`) | выбирает файл | длительность, FPS, разрешение, наличие звука, авторазбиение на тайм-блоки |
| 2 | Создание субтитров (`subtitle_capture`) | пишет текст прямо в поле на кадре (цвет, размер рамки) | хранит блоки и оформление |
| 3 | Озвучка (`voiceover`) | ничего (идёт само после «Сохранить») | Speech Script → TTS по блокам → подгонка длительности |
| 4 | Аннотации (`annotations`) | кликом задаёт рамки/стрелки → «Подтвердить» | сборка готового MP4 и скачивание |

Отдельного шага «Экспорт» нет: файл собирается сразу после подтверждения аннотаций.
Код экспорта сохранён как внутренний (`LEGACY_UI_STAGES`).

## Этап 1 — загрузка и разбиение

- `src/services/video_probe_service.py` → `video_meta.json`
  (длительность, FPS, ширина/высота, наличие аудио).
- `src/services/timeblock_service.py` → `time_blocks.json`.
  Границы блоков берутся из пауз в звуке (`silencedetect`) и смены картинки (`select=scene`),
  затем слишком длинные блоки делятся на равные части.
- Настройки в `.env` (значения по умолчанию в `src/config.py`):
  `BLOCK_MIN_SECONDS=2.5`, `BLOCK_MAX_SECONDS=12`, `BLOCK_TARGET_SECONDS=7`,
  `BLOCK_SILENCE_NOISE_DB=-32`, `BLOCK_SILENCE_MIN_SECONDS=0.45`, `BLOCK_SCENE_THRESHOLD=0.35`.

Запускается автоматически сразу после загрузки видео (`_schedule_processing` в `src/api/app.py`).

## Этап 2 — субтитры на видео

Формат блока в `time_blocks.json`:

```json
{ "id": 15, "start": 84.2, "end": 90.5, "subtitle": "Открываем документ реализации", "status": "edited" }
```

`status`: `empty` (текста нет), `edited` (текст введён), `saved` (нажата кнопка «Сохранить»).

- Сервис: `src/services/subtitle_capture_service.py`
- Интерфейс: `review-ui/src/SubtitleCaptureEditor.tsx`
- API:
  - `GET /jobs/{job_id}/capture` — видео, блоки, оформление субтитра
  - `PUT /jobs/{job_id}/capture` — автосохранение черновика
  - `POST /jobs/{job_id}/capture/save` — кнопка «Сохранить»
  - `POST /jobs/{job_id}/capture/split` — разделить блок в секунде плеера
  - `POST /jobs/{job_id}/capture/merge` — склеить со следующим
  - `POST /jobs/{job_id}/capture/rebuild` — пересобрать разбивку (текст сохраняется)
  - `PUT /jobs/{job_id}/capture/layout` — размер, положение, цвет субтитра

По кнопке «Сохранить» дополнительно пишутся внутренние артефакты для следующих этапов:
`subtitles.srt`, `subtitle_timing.json`, `clean_transcript.json` (совместимость с аннотациями и сборкой).

Любая правка текста после сохранения сбрасывает `saved_at`: озвучку нужно запустить заново.

## Этап 3 — озвучка

После `POST /jobs/{id}/capture/save` сервер сам ставит в фон этап `voiceover`.
После успешной озвучки автоцепочка запускает генерацию предложений аннотаций
(`AUTO_CHAIN_UI`: `voiceover` → `annotations`). Подтверждение аннотаций и экспорт — вручную.

`src/services/auto_voiceover_service.py`:

1. Субтитр → Speech Script (`src/services/speech_script_auto.py`): смысл сохраняется.
   «НДС» → короткое «эн дэ эс» (не полная расшифровка), «№» → «номер».
2. TTS отдельно на каждый блок.
3. Проверка длительности относительно блока (`VOICEOVER_SLOT_TOLERANCE_SECONDS`, по умолчанию 0.6 с).
4. Если не влезает — сначала ускорение речи (до 1.35×), затем только мягкое сокращение связок.
   Жёсткая обрезка предложения запрещена: озвучка не должна терять текст субтитра.
5. Только если и это не помогло — предупреждение пользователю (поле `notice` у этапа).

Результат: `voiceover.wav`, `voiceover_segments.json`, `speech_script_auto.json` (внутренний),
`edited_video.mp4`, `edited_video_with_subtitles.mp4` (превью).

Актуальность отслеживается хешем субтитров (`subtitles_hash`): изменили текст — этапы 3–5 снова не готовы.

## Этап 4 — аннотации

Без изменений по механике: ИИ предлагает момент и объект (`placement_confirmed: false`),
координаты задаются кликом по кадру и сохраняются в `approved_annotations.json`.

## Этап 4 — аннотации и скачивание

Без отдельного шага «Экспорт»: после «Подтвердить» сервер сам вызывает `run_lesson_assembly`:

1. берёт `edited_video.mp4` (уже с озвучкой),
2. прожигает субтитры **точно** с оформлением из `subtitle_layout.json` (цвет фона, размер рамки),
3. накладывает утверждённые аннотации,
4. отдаёт `final_lesson.mp4` на скачивание в том же шаге 4.

## Ключи и безопасность

API-ключи (Yandex, OpenAI, ElevenLabs) хранятся только в `.env`, в коде их нет.
